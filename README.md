# sonarqube-selfhosted

[![CI](https://github.com/vynazevedo/sonarqube-selfhosted/actions/workflows/ci.yml/badge.svg)](https://github.com/vynazevedo/sonarqube-selfhosted/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/vynazevedo/sonarqube-selfhosted)](https://github.com/vynazevedo/sonarqube-selfhosted/releases)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Self-hosted SonarQube Community Build for your GitHub org. After configuring DNS, remote state and access, `terraform apply` provisions `https://sonar.yourdomain.com` on AWS with TLS, backups, snapshots and no SSH surface. A compose-only path is included for any other host.

```mermaid
flowchart LR
    U[Users and CI] -->|443| EIP[Elastic IP]
    subgraph EC2 [EC2 t4g.large, no SSH, SSM only]
        C[Caddy TLS] -->|9000| S[SonarQube]
        S -->|5432| P[PostgreSQL 16]
    end
    EIP --> C
    S --- V[(Data EBS volume)]
    P --- V
    EC2 -.->|password at boot| SSM[SSM Parameter Store]
    EC2 -.->|daily pg_dump| S3[(S3 backups)]
    DLM[DLM snapshots] -.-> V
```

## Features

- Single instance, low cost (region-dependent cost), sized for small and mid-sized orgs
- Automatic HTTPS via Caddy and Let's Encrypt, security headers included
- Database password generated by Terraform, delivered via SSM Parameter Store, never in tfvars or user data
- No SSH: SSM Session Manager only, IMDSv2 required, encrypted gp3 volumes
- State on a dedicated EBS volume: instance replacement and upgrades keep all data
- Daily pg_dump to S3 plus daily EBS snapshots (DLM), automatic instance recovery alarm
- PostgreSQL never exposed; only Caddy publishes ports 80/443

## Quickstart (Terraform)

Prerequisites: a domain you control, AWS credentials and Terraform >= 1.10 for the examples. Configure remote state as described below before applying.

```bash
git clone https://github.com/vynazevedo/sonarqube-selfhosted.git
cd sonarqube-selfhosted/terraform/examples/complete
cp backend.tf.example backend.tf
cp backend.hcl.example backend.hcl
# Edit backend.hcl with your existing state bucket, key and region.
terraform init -backend-config=backend.hcl
terraform apply -var domain=sonar.example.com -var acme_email=you@example.com
```

Point your DNS A record at the `public_ip` output (or pass `-var route53_zone_id=...` to automate it). Any DNS provider works; with Cloudflare, create the record in DNS-only mode (grey cloud) so the ACME challenge reaches Caddy directly. After 5 to 10 minutes, open the URL, log in with `admin` / `admin` and change the password immediately.

To embed in your own Terraform, pin a release:

```hcl
module "sonarqube" {
  source = "github.com/vynazevedo/sonarqube-selfhosted//terraform?ref=v0.1.0"

  vpc_id     = "vpc-0abc123"
  subnet_id  = "subnet-0def456"
  domain     = "sonar.example.com"
  acme_email = "you@example.com"
}
```

## Module inputs

Required: `vpc_id`, `subnet_id`, `domain`, `acme_email`.

| Name | Default | Description |
| --- | --- | --- |
| `name` | `sonarqube` | Name prefix for all resources |
| `instance_type` | `t4g.large` | With `architecture = x86_64` for Intel types |
| `allowed_cidrs` | `["0.0.0.0/0"]` | CIDRs allowed on 80/443 |
| `data_volume_size` | `50` | Persistent volume (GiB) at /var/lib/docker |
| `data_volume_snapshot_id` | `null` | Restore the data volume from a snapshot |
| `route53_zone_id` | `null` | Create the DNS record automatically |
| `create_backup_bucket` | `true` | Daily pg_dump to S3 |
| `backup_retention_days` | `30` | S3 backup expiry |
| `enable_dlm_snapshots` | `true` | Daily EBS snapshots |
| `snapshot_retention_days` | `7` | Snapshots retained |
| `enable_cloudwatch_alarms` | `false` | CPU, disk, HTTPS health and backup freshness alarms |
| `alarm_actions` | `[]` | SNS topics for alarms |
| `sonarqube_image` | `sonarqube:26.9.0.129388-community` | Pin an exact patch in production |
| `extra_env` | `{}` | Extra .env entries, for example JVM heaps |

Full list with descriptions in [terraform/variables.tf](terraform/variables.tf); outputs in [terraform/outputs.tf](terraform/outputs.tf).

## Production preparation

Use a dedicated S3 state bucket with encryption, versioning, public access blocked and restricted IAM access. The example backend enables S3 locking (`use_lockfile`); grant access to the state object and its `.tflock` object. Never commit state, backend credentials or real tfvars. Terraform state contains the database password even though the value is marked sensitive. Keep AWS credentials in your profile, for example `AWS_PROFILE=cia`, not in backend files.

Enable `enable_cloudwatch_alarms` and supply SNS topic ARNs in `alarm_actions`. Application checks run on the instance against the public HTTPS URL; they are not an independent external uptime probe. Missing metrics alarm after three periods. Backup freshness alarms until the first successful backup; run one manually after installation. If ingress is restricted, allow the instance to reach its public endpoint as well as CI runners, and arrange ACME validation accordingly.

Before opening access to the organization, change the initial admin password, configure GitHub authentication with allowed organizations, make internal projects private, review permissions and complete a restore drill. A single EC2 instance is not highly available. The deployment is not operationally verified merely by passing Terraform validation.
